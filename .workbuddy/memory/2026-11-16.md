## 端口 80 → 8080（为内网穿透）

- **服务托管方式（重要）**：Windows 计划任务 `ZDR-Prototype-Web`，Principal=SYSTEM / ServiceAccount / RunLevel=Highest，Trigger=`MSFT_TaskBootTrigger`（开机自启），Action=`C:\nvm4w\nodejs\node.exe "…\deploy\zdr-prototype\server.js"`，WorkingDirectory=deploy/zdr-prototype。**改端口/重启服务应操作这个计划任务，不要手动起 node**（手动起的会被任务管理的实例冲突）。
- 改动：`server.js` 默认端口 `process.env.PORT || 80` → `|| 8080`（并更新头部注释）。计划任务无 PORT 环境变量，故直接生效。
- 防火墙：`New-NetFirewallRule -DisplayName 'ZDR-Prototype-HTTP-8080' -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow -Profile Any`。原规则 `ZDR-Prototype-HTTP-80` 保留未删（回滚用）。
- 重启：`Stop-ScheduledTask` → `Start-ScheduledTask -TaskName 'ZDR-Prototype-Web'`；新 PID 47016，监听 0.0.0.0:8080，80 已释放。
- 新地址：http://192.168.10.90:8080/ （总览页）、http://192.168.10.90:8080/login.html。
- 同步更新文档：`docs/prototype-v2/演示全书-系统讲解与需求映射-V2.2.md` 两处 URL 加 `:8080`。

## 本机代理环境（排查"浏览器/curl 502"必读）

- 代理客户端：**Clash Verge**（`D:\Clash Verge\verge-mihomo.exe`，PID 26100），mixed-port **7897**，`mode: rule`，**TUN 关闭**（无虚拟网卡），属系统代理模式。
- Windows 系统代理：`ProxyEnable=1`，`ProxyServer=127.0.0.1:7897`，`ProxyOverride` 已含 `192.168.*`（另有 10.*、172.16~31.*、localhost、`<local>`），故**浏览器访问 192.168.10.90 默认直连**。
- 会话 shell 另有一套注入的环境代理：`http_proxy/https_proxy=127.0.0.1:54811`（WorkBuddy 宿主），`NO_PROXY` 只有 `127.0.0.1,localhost,::1` → curl 打 `192.168.10.90` 会经它转发，端口无服务时返回 **502** 而非连接拒绝。
- 实测（headless Chrome，去掉 proxy 环境变量）：系统默认 / `--proxy-server=http://127.0.0.1:7897` / `--no-proxy-server` 三种路径访问 `http://192.168.10.90:8080/login.html` **均正常加载**；访问旧 `http://192.168.10.90/`（80 已停）返回空白错误页。
- 结论：8080 访问不受代理影响；"502"只出现在访问已关闭的 80 端口时。断言端口是否存活用 `curl --noproxy '*'`。
