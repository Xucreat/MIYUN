## 1 文档说明

### 1.1 编写目的

本文件定义密云区重点风险人员台账管理与风险预警系统一期工程的功能需求、数据需求与非功能需求，作为系统设计、开发、测试和验收的共同依据。

### 1.2 适用范围

适用于一期（2026 年底 Demo 雏形阶段）及向正式建设期延伸的需求基线。远期社会治安综合治理平台的需求在《14-社会治安综合治理平台总体规划》中另行描述，不在本文件范围。

### 1.3 术语与缩略语

| 术语 | 说明 |
|---|---|
| 一人一档 | 以自然人（身份证号）为唯一主体的档案模型，一个自然人只有一份主档案 |
| 标签 | 人员所属的风险类别（对应 11 类重点人员），一人可持多个标签，现阶段上限 3 个 |
| 双在册 | 同一自然人同时被两个部门列入台账（公安/卫健、公安/信访） |
| 就高不就低 | 一人多标且分级不同时，管控标准按最高等级执行 |
| 列控级别 | 邪教人员、政保重点人使用的分级口径（一级/二级/三级/关注对象） |
| 驾驶舱 | 面向区领导的全局可视化首页 |
| 重点时期 | 全国两会、国庆、重大庆典等敏感节点 |

### 1.4 需求编号规则

`FR-<模块缩写>-<两位序号>`，模块缩写：TZ（台账）、FX（风险）、YJ（预警）、KS（可视化）、CX（查询导出）、XT（系统管理）。非功能需求为 `NFR-<类别>-<序号>`。

## 2 项目背景与建设目标

### 2.1 背景

按区委政法委统一部署，区公安分局、区信访办、区卫健委等行业主管部门已对本领域重点人员完成全面起底。经身份标签比对查重，全区重点人员归并为 11 类、约 6000 人，存在两类突出特征：

1. **双在册人员**：公安卫健双在册严重精神障碍患者、公安信访双在册涉访人员，共计数百人；
2. **多重身份标签人员**：同一自然人持有 2 个以上身份标签，标签多、隐患杂、风险维度叠加，易形成管控盲区。

当前台账分散在各部门、格式不一、更新靠报表，无法支撑"底数清、情况明、动态准、管得住"的工作要求，也无法应对 2027 年政治大年的安全稳定形势。

### 2.2 建设目标

**近期目标（2026 年底前）**：建成重点风险人员台账管理模块雏形，实现实名制一人一档、风险等级动态调整、标签查重并档、组合查询、全局可视化驾驶舱与三级权限管控，形成可向区领导汇报的 Demo。

**中期目标（一期正式建设）**：与公安、信访、卫健、司法四部门建立数据推送与更新闭环，实现风险等级变动的月度报送、双在册与多标人员的自动识别与重点关注标识，支撑重点时期名单快速提取与"每日见面、每日零报告"的落实留痕。

**远期目标**：依托本系统扩展为全区社会治安综合治理平台，整合防汛应急、征地拆迁等重点领域风险预警（意向待定，不在本期）。

### 2.3 建设原则

1. **管理定位清晰**：本系统承担行政层面的台账管理与宏观研判，不替代公安垂直业务系统与专业研判模型，避免重复建设。
2. **数据不出域**：全量数据本地化部署，不向区外传输，不调用外部公有云大模型接口处理实名数据。
3. **最小必要**：按岗位职责授权到字段级，查询、导出、更新全过程留痕。
4. **就高不就低**：多标人员管控标准取最高等级，系统在档案与驾驶舱双处给出显性提示。
5. **快出雏形**：Demo 阶段以虚拟数据跑通全流程，优先保证可汇报、可演示、可扩展。

1. 公安专业数据（网购记录、轨迹、报警记录等）的接入与建模；

4. 与市级综治平台的双向业务流转（仅预留接口，见 09 文档）；
5. 面向公职人员的通用 AI 办公助手、"京办"能力替代；
6. 应急指挥调度、防汛、征地拆迁等拓展场景。

### 3.3 与外部系统的关系

| 外部系统 | 关系 | 边界约定 |
|---|---|---|

## 4 用户角色与典型场景

### 4.1 角色定义

| 角色 | 岗位举例 | 核心诉求 | 数据范围 |
|---|---|---|---|
| 区领导 | 区委区政府领导、政法委书记 | 全局概览、风险态势、重点人分布 | 全区汇总数据 + 人员概要（身份证号掩码） |
| 主管部门管理员 | 政法委主管科室、书记/科长 | 辖区与部门数据审核、等级审批、督办 | 所辖范围全字段 |
| 部门经办人 | 公安、信访、卫健、司法经办 | 本部门台账维护与更新 | 本部门数据全字段，其他部门数据仅可见公共字段 |
| 属地经办人 | 镇街综治中心 | 辖区人员走访、状态反馈 | 本辖区人员，可写走访记录 |
| 系统管理员 | 运维 | 账号、权限、字典、日志 | 不含业务明细（无查看权限时的默认隔离） |
| 安全审计员 | 政法委/网安 | 日志审查 | 仅日志 |

### 4.2 典型场景

**场景 A｜重点时期名单提取**：两会前 10 日，政法委主管登录系统，筛选"风险等级为高风险及以上 + 居住地在城区街道 + 近 30 日无走访记录"的人员，一键导出行程盯控名单，分发至属地，属地回填见面状态，系统形成"应见未见"清单。

**场景 B｜双在册人员并档**：卫健推送新增严重精神障碍患者台账，系统按身份证号比对发现该人已在公安台账中，自动合并为一份档案、挂 2 个标签，标注"双在册"标识，并将管控标准置为两部门中较高者，同时向两部门经办推送待确认任务。

**场景 C｜风险等级调整**：属地提交等级下调申请（附走访记录与研判意见），主管部门审批通过后，档案等级变更，历史等级留痕，驾驶舱高风险人数与趋势同步刷新。

**场景 D｜多标人员研判**：区领导在驾驶舱点击"多重标签人员"指标，下钻查看持有 3 个标签且风险等级较高的人员清单，按标签组合（如"涉访 + 精神障碍 + 六失一偏"）分组查看，辅助部署联合管控。

## 5 业务对象与数据口径

### 5.1 管理对象规模

| 口径 | 规模 | 说明 |
|---|---|---|
| 台账记录数（按人·次数） | 约 6000 人次量级 | 各部门报送的台账原始记录 |
| 去重后自然人 | 少于台账记录数 | 以身份证号为唯一键去重 |
| 双在册人员 | 数百人 | 公安卫健、公安信访 |
| 多重标签人员 | 数百人 | 2 个及以上标签 |

> 具体数值以政府侧正式提供的脱敏统计为准，Demo 阶段使用虚拟数据按上述量级等比生成。

### 5.2 十一类人员与分级口径

| 序号 | 类别 | 分级口径 | 主责部门 |
|---|---|---|---|
| 1 | 社区矫正对象 | 高 / 中 / 低 | 司法行政 |
| 2 | 安置帮教人员 | 高 / 中 / 低 | 司法行政 |
| 3 | 吸毒人员 | 个人极端 / 高 / 中 / 低 | 公安 |
| 4 | 严重精神障碍患者 | 高 / 中 / 低 / 风险不详（拒访、失访） | 卫健、公安 |
| 5 | 有严重不良行为未成年人 | 高 / 中 / 低 | 公安、教育 |
| 6 | 扬言类重点人 | 高 / 中 / 低 / 一般关注 / 未定级 | 公安 |
| 7 | 涉访关注人员 | A / B / C 类 | 信访、公安 |
| 8 | 邪教人员 | 一级 / 二级 / 三级 / 关注对象 | 公安 |
| 9 | 政保重点人 | 一级 / 二级 / 三级 / 关注对象 | 公安 |
| 10 | 反恐关注群体人员 | 高 / 中 / 低 / 无 | 公安 |
| 11 | "六失一偏"人员 | 高 / 中 / 低 / 一般关注 / 未定级 | 政法、民政 |

**关键规则**：11 类为当前基线，类别可动态增补；不同类别分级口径不同，系统需维护"类别—等级"映射字典，并归一化出一个**统一风险序**（见《07-业务规则与风险分级口径说明》）用于跨类别排序、筛选与"就高不就低"计算。

### 6.2 台账管理

| 编号 | 需求名称 | 描述 | 验收要点 |
|---|---|---|---|
| FR-TZ-01 | 一人一档 | 以身份证号为唯一键建立人员主档案，含基本信息、标签、风险等级、责任属地、包联干部 | 同一身份证号重复导入不产生第二份档案 |
| FR-TZ-02 | 建档与录入 | 支持表单录入与批量导入两种方式建档，必填项校验、身份证号格式与校验位校验 | 非法身份证号被拦截并给出错误行定位 |
| FR-TZ-03 | 标签维护 | 为人员增加/移除类别标签，单标签需记录列入原因、列入时间、来源部门；标签数超 3 时告警并需主管审批 | 第 4 个标签被拦截或进入审批流程 |
| FR-TZ-04 | 档案变更 | 支持基本信息、责任属地、包联干部、联系方式等字段变更，变更需留痕（变更前/后值、操作人、时间） | 变更历史可完整回溯 |
| FR-TZ-05 | 人员消减 | 支持迁出、死亡、撤管等原因消减，保留历史档案不物理删除 | 消减后不再进入统计口径，但可按"已消减"筛选查询 |
| FR-TZ-06 | 双在册识别 | 自动识别公安卫健、公安信访同一自然人的双部门在册关系并标注 | 新增数据后自动完成识别，无需人工触发 |
| FR-TZ-07 | 多标合并与标识 | 多标签人员自动合并为一份档案，标注"多重标签"与标签数量，并按就高不就低给出管控标准 | 驾驶舱可筛选"标签数 ≥2 / ≥3" |
| FR-TZ-08 | 走访与沟通记录 | 记录走访时间、方式、情况、发现的问题、下一步措施；记录公安沟通记录 | 走访记录可按人员、时间、属地检索，可统计"近 N 日未走访" |

### 6.3 风险管理

| 编号 | 需求名称 | 描述 | 验收要点 |
|---|---|---|---|
| FR-FX-01 | 等级维护 | 按类别维护其分级取值（含风险不详、未定级、无等特殊值） | 各分类级取值与 5.2 表一致 |
| FR-FX-02 | 等级调整 | 发起调整申请（上调/下调）、填写评估依据、逐级审批、通过后生效并留痕 | 调整需审批；无审批直接变更被禁止 |
| FR-FX-03 | 评估依据管理 | 每条档案保存风险等级评估依据，支持附件（研判意见、诊断材料、判决文书等） | 依据缺失时可配置为"不允许上调等级" |
| FR-FX-04 | 统一风险序 | 提供跨类别归一化风险排序，用于筛选与驾驶舱"高风险及以上"口径 | 11 类不同分级可正确比较大小 |
| FR-FX-05 | 就高不就低计算 | 多标人员自动取最高等级作为管控标准等级，并保留各标签原始等级 | 两标签一高一低时，管控等级为高 |
| FR-FX-06 | 等级变动台账 | 按月生成等级变动清单，供政法委月度报送 | 可按月份导出变动明细 |

### 6.4 预警与研判（一期简版）

| 编号 | 需求名称 | 描述 | 验收要点 |
|---|---|---|---|
| FR-YJ-01 | 规则预警 | 内置规则：近 N 日未走访、等级下调后 N 日内无随访、双在册未确认、多标高风险未包联、失访/拒访超期 | 规则可配置阈值与开关 |
| FR-YJ-02 | 预警处置 | 预警生成待办，指派至责任人，处置后闭环并留痕 | 预警有状态流转（待处置/处置中/已闭环/已忽略） |
| FR-YJ-03 | 重点关注标识 | 高风险、双在册、多标人员自动打"重点关注"标识，支持人工追加 | 标识可在档案、列表、驾驶舱统一显示 |
| FR-YJ-04 | 关键词风险提示 | 基于走访记录、沟通记录文本，做涉稳关键词命中提示（本地规则词典 + 本地模型），仅提示不自动定级 | 命中结果需人工确认，可关闭 |
| FR-YJ-05 | 接处警/外部门线索登记 | 支持手工登记外部推送的风险线索，关联到人员档案 | 线索与档案可双向查看 |

| FR-CX-05 | 导入 | 提供标准模板，支持四部门台账 Excel 导入、字段映射、错误回显、导入批次追溯 | 错误行可下载修正后重传 |

## 7 数据需求

### 7.1 数据来源与更新责任

| 数据类别 | 来源单位 | 更新方式 | 频次 | 责任 |
|---|---|---|---|---|
| 社区矫正、安置帮教 | 区司法局 | Excel 台账导入 | 每月 | 司法行政 |
| 吸毒、扬言、邪教、政保、反恐、不良行为未成年人 | 区公安分局 | Excel 台账导入（规划为接口） | 每月 | 公安 |
| 严重精神障碍患者 | 区卫健委、公安分局 | Excel 台账导入 | 每月 | 卫健、公安 |
| 涉访关注人员 | 区信访办、公安分局 | Excel 台账导入 | 每月 | 信访、公安 |
| "六失一偏"人员 | 区委政法委、民政 | Excel 台账导入 | 每月 | 政法委、民政 |
| 走访记录 | 属地镇街 | 系统录入 | 实时 | 属地 |
| 公安重点关注结论 | 公安分局 | 接口/文件 | 按需 | 公安 |

**更新闭环**：行业部门与属地发生风险调整、人员增减时，第一时间在本系统更新，每月向区委政法委报送，系统自动生成月度报送清单与差异说明（谁未报、谁迟报）。

### 7.2 数据质量要求

1. 身份证号是唯一键，必填且需通过校验位验证；无身份证号人员（极少）使用临时编号并标注，不得进入去重统计。
2. 姓名、类别、风险等级、责任属地、来源部门为必填字段。
3. 同一人员同一标签不得重复；标签重复导入需合并而非追加。
4. 风险等级评估依据缺失的人员，在列表与档案中显式标记"依据缺失"，并在统计中单列。
5. 每次导入生成批次记录，可回溯到源文件与导入人。
