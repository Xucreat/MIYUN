## 1 文档用途

本文件定义系统的数据标准，承担四项职能：

1. **建库依据**：数据库表结构与字段类型的设计来源；
2. **接入依据**：四部门台账导入时的字段映射与校验规则；
3. **合规依据**：敏感字段的密级划分、脱敏形态与授权方式；
4. **追溯依据**：数据质量问题的判定标准与处理方式。

逐表块的字段级映射（含公安 11 个表块的具体列位）见《02A-部门台账表头一致化方案》，本文档不重复列示。

## 2 数据标准总览

### 2.1 三层字段模型

| 层 | 定位 | 字段数 | 存储方式 | 是否跨部门对齐 |
|---|---|---|---|---|
| L1 主干层 | 区级管控决策的最小必要集 | 22 | `person` 表独立列 | 是，强制对齐 |
| L2 类别扩展层 | 11 类各自的专业判断字段 | 118 | `person_ext.detail`（JSONB） | 否，按类别挂载 |
| L3 原始留存层 | 部门专业数据与内部编码 | 73 | `raw_ledger.raw_json` | 否，原样保存 |

**设计依据**：四部门 253 个字段名中，跨部门同名可用的仅 7 个，字段一致率不足 3%。若强行要求全部字段对齐，需要部门重填报表，不具备可执行性；若不做对齐，则无法形成统一底数。三层模型将真正需要统一的字段压缩至 22 个，其余按类别存放或原样留存，兼顾统一性与可执行性。

### 2.2 数据模型总览

| 表名 | 中文名 | 说明 | 3 年记录量级 |
|---|---|---|---|
| `person` | 人员主档 | 一人一条，身份证号哈希唯一 | 约 6000 |
| `person_tag` | 人员标签 | 一人多标，含类别内等级 | 约 8100 |
| `person_ext` | 类别扩展 | 按类别存专业字段 | 约 8100 |
| `risk_change` | 等级变动 | 每次调整一条，含审批 | 万级 |
| `visit_record` | 走访沟通记录 | 走访、电话、约谈、沟通 | 十万级 |
| `alert` | 预警待办 | 规则命中生成 | 万级 |
| `import_batch` | 导入批次 | 每文件每表块一条 | 千级 |
| `raw_ledger` | 原始台账 | 原样留存，只增不改 | 十万级 |
| `group_ledger` | 群体台账 | 涉访群体、关注群体等群体级数据 | 百级 |
| `attachment` | 附件 | 研判意见、诊断材料等 | 万级 |
| `audit_log` | 审计日志 | 全量留痕，按月分区 | 百万级 |

**群体台账单列的原因**：公安"密云分局在册涉访群体"（12 列）与"密云区常住关注群体人员统计表"（8 列）为群体级统计，含"群体涉及人数""2024 年以来活跃人数"等字段，不含完整个人身份信息。此类数据不进入人员主档，避免污染"一人一档"口径。

## 6 部门台账接入规则

### 6.1 表块识别

一个部门文件可能包含多个业务表块（公安.xls 含 11 个），导入时须先切块再映射：

1. 扫描标题行：单非空单元格且该行列数大于 3；
2. 以标题关键词匹配到类别（如"吸毒人员列表"→吸毒人员）；
3. 标题未命中时进入人工绑定，绑定结果保存为该部门的表块配置；
4. 每块独立生成映射配置，独立生成导入批次。

### 6.2 字段映射

- 按**列序号**定位，不按名称匹配（公安涉访表存在两个同名"联系方式"，分属责任领导与责任民警）；
- 映射配置按"部门 + 表块"维度保存，后续同类文件复用；
- 未配置的列默认进入 L3 原始留存，不影响导入；
- 映射结果支持预览：上传后先展示"源列名 → 目标字段 → 样例值"，确认后执行。

### 6.3 清洗规则

| 规则 | 处理 |
|---|---|
| 空值识别 | `""`、`—`、`/`、`无`、`NULL` 统一识别为 NULL |
| 日期格式 | 支持 `2026-11-05`、`2026/11/5`、`20261105`、Excel 日期序列号，统一转 `YYYY-MM-DD` |
| 合并列拆分 | "监护人姓名及电话""精防医生姓名及电话""镇街主管领导姓名及电话"按正则拆分；失败整列入 L2 并标记 |
| 同义转换 | 按同义词字典转换类别、等级、状态表述，转换项写入批次报告 |
| 地址解析 | 由现住址解析责任镇街，解析失败置空并进入待补清单 |
| 年龄换算 | 由年龄反推出生日期（按当年 12 月 31 日估算），精度不足时标注 |

## 7 查重、并档与标签规则

### 7.1 唯一性

1. 主键为身份证号标准化结果（去空格、末位 X 大写），另存 HMAC-SHA256 哈希用于唯一索引与等值查询；
2. 校验：18 位、前 17 位数字、校验位正确、出生日期段合法；
3. 校验不通过但有值 → 进入"待核实池"，人工确认后可手工编号入库；
4. 无身份证号 → 临时编号 `TMP-镇街码-序号`，不参与去重率计算；
5. 公安表中"证件号码""当事人证件号码"可能为护照等其他证件，识别后以"证件类型 + 号码"组合作唯一键。

### 7.2 并档规则

| 场景 | 处理 |
|---|---|
| 同号、同类别、同部门 | 合并为一条标签，更新列入原因与时间取最新，累加走访记录 |
| 同号、同类别、不同部门 | 保留两条标签（双在册物理表达），置 `is_dual_reg`，管控等级取高，生成双部门确认任务 |
| 同号、不同类别 | 保留多个标签，`tag_count` 递增，置多标标识 |
| 同名、不同号 | **不合并**，档案页提示"存在同名人员 N 人" |
| 不同号、同一人（疑似） | 不自动合并；通过"疑似重复"清单人工确认，确认后手工并档并留痕 |

### 7.3 双在册与多重标签的区分

| 情形 | 标签数 | 双在册 | 多重标签 |
|---|---|---|---|
| 精神障碍患者，公安与卫健均在册 | 1（同类两源） | 是 | 否 |
| 涉访人员，公安与信访均在册 | 1（同类两源） | 是 | 否 |
| 既是精神障碍患者，又是涉访人员 | 2 | 是 | 是 |
| 仅卫健在册的精神障碍患者 | 1 | 否 | 否 |

**判定口径**：双在册看部门数，多重标签看类别数，两者独立计算、可同时为真。卫健表"是否公安列管"字段作为双在册的正向标识，同时以身份证号碰撞做双向校验。

### 7.4 标签上限

| 标签数 | 处理 |
|---|---|
| 1—3 | 正常合并 |
| 4—6 | 需主管部门审批后允许，进入"重点多重标签"清单 |
| 7 及以上 | 需政法委专题研判，说明重复认定原因 |

## 8 脱敏与密级规范

### 8.1 密级定义

| 密级 | 含义 | 字段示例 | 默认可见 |
|---|---|---|---|
| L1 | 内部一般 | 类别、等级、镇街、状态、时间 | 全部授权用户 |
| L2 | 敏感 | 姓名、住址、监护人、责任人 | 区领导掩码，主管与属地明文 |
| L3 | 高敏 | 身份证号、手机号 | 掩码；明文需审批 |
| L4 | 特殊内容 | 诊断、组织类别、涉访诉求、扬言内容、原罪名、评估依据 | 仅本部门可见；跨部门仅见"存在该标签" |

### 8.2 掩码算法

| 字段 | 规则 | 示例 |
|---|---|---|
| 姓名 | 保留首字 | 任玉荣 → 任** |
| 身份证号 | 前 6 后 4 | 110118********1234 |
| 手机号 | 前 3 后 4 | 138****5678 |
| 住址 | 保留镇街社区，门牌掩码 | 鼓楼街道**社区**号 |
| 监护人/责任人姓名 | 同姓名规则 | 蔡** |
| 长文本（诉求、诊断、依据） | 按角色整体不可见 | — |

### 8.3 明文授权

申请（人员范围、用途、有效期，默认 24 小时）→ 审批（申请人不得自审；超过 50 条或涉未成年人需第二审批人）→ 生成限时令牌（绑定账号、IP 段）→ 访问留痕（含审批单号）→ 到期失效或提前撤回。导出文件加隐形水印（账号 + 时间戳）。

### 8.4 存储与传输

身份证号、手机号、监护人信息采用应用层加密（SM4 或 AES-256-GCM），密钥独立管理、不与数据库同机存放；传输采用国密 TLS 或 TLS1.2+；备份文件加密。

## 9 虚拟数据生成规则

原型阶段的虚拟数据须满足"格式真实、内容虚构、可校验"。

| 数据类型 | 生成规则 |
|---|---|
| 姓名 | 百家姓 + 随机双字名，规避与样例重名 |
| 身份证号 | 区划码 110118，出生日期 1940—2010 随机，校验位按国标算法计算 |
| 手机号 | 199 号段顺序编号（19900000001 起） |
| 住址 | 真实镇街 + 虚构小区 + 虚构楼栋 |
| 镇街分布 | 20 个镇街真实行政区划，鼓楼、果园街道占比高 |
| 类别分布 | 11 类齐备，占比参照部门台账相对量级 |
| 特殊样本 | 双在册 ≥20 例；3 标签 ≥10 例；风险不详/失访 ≥10 例；已消减 ≥10 例；同名不同人 ≥5 例；无身份证号 ≥3 例 |
| 走访记录 | 每人 0—6 条，跨 12 个月，含"近 30 日未走访"样本 |
| 等级变动 | 每人 0—2 条，含上调与下调 |

规模：6000 人主档、8100 条标签、12000 条走访、600 条变动、300 条预警。生成脚本随工程交付，随机种子固定，结果可重现。

## 10 数据质量校验规则

| 编号 | 规则 | 处理 |
|---|---|---|
| DQ-01 | 身份证号必填且校验位正确 | 错误行进待核实池 |
| DQ-02 | 姓名非空，长度 2—20 | 拦截 |
| DQ-03 | 性别与身份证第 17 位一致 | 不一致以身份证为准并告警 |
| DQ-04 | 镇街在 20 个镇街字典内 | 拦截，提示相近值 |
| DQ-05 | 类别在 11 类字典内 | 拦截 |
| DQ-06 | 等级在该类别的分级字典内 | 拦截，或按同义词字典转换 |
| DQ-07 | 同批次内身份证号 + 类别不重复 | 自动合并并计数 |
| DQ-08 | 列入原因为空 | 允许入库，标记"原因缺失" |
| DQ-09 | 评估依据为空 | 标记"依据缺失"，限制等级下调 |
| DQ-10 | 现住址为空 | 不参与地图分布，单列待补 |
| DQ-11 | 责任镇街解析失败 | 置空并入待补清单，不影响其他字段 |
| DQ-12 | 合并列拆分失败 | 整列入 L2，标记"待拆分" |

## 11 导入模板与批次管理

### 11.1 模板体系

系统预置 15 套模板（对应 15 个表块），而非 4 套部门模板：

| 部门 | 模板数 | 说明 |
|---|---|---|
| 公安 | 11 | 涉访群体、刑释不满五年、常住关注群体、六失一偏、精神障碍、邪教、社区矫正、吸毒、扬言、不良行为未成年人、涉访关注 |
| 司法 | 2 | 社区矫正、安置帮教 |
| 卫健 | 1 | 严重精神障碍患者 |
| 信访 | 1 | 信访关注人员 |

模板与部门实际报表列序一致，部门按原格式导出即可导入，无需调整列顺序。

### 11.2 批次报告

每次导入生成报告，包含：成功行数、失败行数、合并行数、新增标签数、新增人员数、已转换同义项清单、拆分失败清单、错误明细（可下载，含源行号与原值）。

### 11.3 幂等与留档

- 幂等键：`文件哈希 + 部门 + 表块`，重复上传返回既有批次；
- 原始文件与逐行 JSON 全量留档，支持下载核对；
- 批次记录保留导入人、时间、文件摘要，作为数据来源追溯依据。
