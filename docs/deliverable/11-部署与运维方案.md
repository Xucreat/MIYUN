## 1 部署形态

### 1.1 两种形态

| 形态 | 适用场景 | 组件部署 | 特点 |
|---|---|---|---|
| 单机一体化 | 原型演示、隔离网络试用 | 全部组件部署于一台服务器（容器编排） | 部署快、可离线运行，适合演示与网络隔离区 |
| 双机分离 | 正式运行 | 应用节点 2 台 + 数据库主备 + 文件存储 | 满足可用性与等级保护要求 |

### 1.2 正式环境拓扑

### 1.3 网络分区与端口

| 区域 | 组件 | 开放端口 | 访问来源 |
|---|---|---|---|
| 接入区 | 负载均衡、Nginx | 443 | 用户网段 |
| 应用区 | 应用服务 | 8000 | 仅负载均衡 |
| 数据区 | 数据库 | 5432 | 仅应用区 |
| 管理区 | SSH | 22 | 仅堡垒机 |

**出向策略**：应用区默认拒绝一切互联网出向，仅允许访问数据库、文件存储、内部模型服务。该策略在部署时以安全组与主机防火墙双重配置，并留存配置记录作为等级保护测评证据。

| 序号 | 检查项 | 确认内容 |
|---|---|---|
| 1 | 服务器 | 可登录、时间同步（内网 NTP 源）、磁盘挂载正确、时区 Asia/Shanghai |

## 4 部署步骤

### 4.1 编排文件（单机）

```yaml
version: "3.9"
services:
  db:
    image: postgres:16
    restart: always
    environment:
      POSTGRES_DB: zdr
      POSTGRES_USER: zdr_app
      POSTGRES_PASSWORD: ${DB_PASSWORD}
      TZ: Asia/Shanghai
    volumes:
      - /opt/zdr/data/pgdata:/var/lib/postgresql/data
      - /opt/zdr/backup/db:/backup
    command: >
      postgres
      -c shared_buffers=4GB
      -c effective_cache_size=10GB
      -c work_mem=32MB
      -c maintenance_work_mem=512MB
      -c max_connections=150
      -c wal_level=replica
      -c archive_mode=on
      -c archive_command='test ! -f /backup/wal/%f && cp %p /backup/wal/%f'
      -c log_min_duration_statement=1000
      -c random_page_cost=1.1
    ports:
      - "127.0.0.1:5432:5432"

  api:
    build: ./backend
    restart: always
    depends_on: [db]
    environment:
      APP_ENV: prod
      DATABASE_URL: postgresql+asyncpg://zdr_app:${DB_PASSWORD}@db:5432/zdr
      JWT_SECRET: ${JWT_SECRET}
      FIELD_ENC_KEY: ${FIELD_ENC_KEY}
      TZ: Asia/Shanghai
    volumes:
      - /opt/zdr/data/files:/data/files
      - /opt/zdr/logs:/logs
    command: >
      gunicorn app.main:app -k uvicorn.workers.UvicornWorker
      -w 4 -b 0.0.0.0:8000 --timeout 120
    ports:
      - "127.0.0.1:8000:8000"

  web:
    image: nginx:1.25
    restart: always
    depends_on: [api]
    volumes:
      - /opt/zdr/app/frontend/dist:/usr/share/nginx/html:ro
      - /opt/zdr/app/nginx.conf:/etc/nginx/nginx.conf:ro
      - /opt/zdr/certs:/etc/nginx/certs:ro
      - /opt/zdr/logs:/var/log/nginx
    ports:
      - "443:443"
      - "80:80"
```

### 4.2 数据库参数说明

| 参数 | 单机取值 | 双机取值 | 依据 |
|---|---|---|---|
| shared_buffers | 4GB | 8GB | 内存的 25% |
| effective_cache_size | 10GB | 24GB | 内存的 75% |
| work_mem | 32MB | 32MB | 支撑排序与哈希连接 |
| max_connections | 150 | 200 | 应用连接池上限 ×2 冗余 |
| random_page_cost | 1.1 | 1.1 | SSD 介质 |
| log_min_duration_statement | 1000ms | 1000ms | 慢查询捕获 |

### 4.3 部署命令

```bash
# 1 准备环境变量
cd /opt/zdr/app
cp .env.example .env && vi .env      # 填写 DB_PASSWORD / JWT_SECRET / FIELD_ENC_KEY
mkdir -p /opt/zdr/{data/files,logs,backup/db/wal,certs}

# 2 启动数据库
docker compose up -d db && sleep 10

# 3 执行数据库迁移
docker compose run --rm api alembic upgrade head

# 4 初始化（三员账号、组织、角色、字典、镇街）
docker compose run --rm api python -m scripts.init_system

# 5 启动应用与前端
docker compose up -d api web

# 6 健康检查
curl -k https://localhost/healthz
curl -k https://localhost/api/v1/system/ping
```

### 4.4 反向代理要点

```nginx
server { listen 80; return 301 https://$host$request_uri; }

server {
    listen 443 ssl;
    server_name zdr.miyun.local;

    ssl_certificate     /etc/nginx/certs/server.crt;
    ssl_certificate_key /etc/nginx/certs/server.key;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5:!3DES:!RC4;

    add_header X-Frame-Options SAMEORIGIN always;
    add_header X-Content-Type-Options nosniff always;
    add_header Content-Security-Policy "default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self'" always;
    add_header Strict-Transport-Security "max-age=31536000" always;

    client_max_body_size 50m;

    location / { root /usr/share/nginx/html; try_files $uri $uri/ /index.html; }

    location /api/ {
        proxy_pass http://api:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Trace-Id $request_id;
        proxy_read_timeout 180s;
        limit_req zone=api burst=50 nodelay;
    }
}
limit_req_zone $binary_remote_addr zone=api:10m rate=20r/s;
```

内容安全策略禁止加载外部资源，与"数据不出域"要求一致；单次上传限制 50M；接口限流防止暴力查询。

## 7 备份与恢复

### 7.1 备份策略

| 类型 | 频率 | 保留 | 方式 | 存放 |
|---|---|---|---|---|
| 数据库全量 | 每日 02:00 | 30 天 | `pg_dump -Fc` + 校验和 | 本地 + 异地 |
| 事务日志归档 | 持续 | 7 天 | 归档至备份目录 | 本地 + 异地 |
| 文件数据 | 每日 02:30 | 30 天 | 增量同步 | 本地 + 异地 |
| 配置与代码 | 每次变更 | 全部 | 版本库 + 配置快照 | 代码库 |
| 离线介质 | 每周 | 3 个月 | 加密拷贝 | 保密柜 |

### 7.2 备份脚本

```bash
#!/bin/bash
set -e
DATE=$(date +%Y%m%d_%H%M)
DIR=/opt/zdr/backup/db
KEEP=30

docker exec zdr-db pg_dump -U zdr_app -Fc zdr > ${DIR}/zdr_${DATE}.dump
sha256sum ${DIR}/zdr_${DATE}.dump > ${DIR}/zdr_${DATE}.sha256
rsync -a --delete /opt/zdr/data/files/ /opt/zdr/backup/files/
find ${DIR} -name "zdr_*.dump"   -mtime +${KEEP} -delete
find ${DIR} -name "zdr_*.sha256" -mtime +${KEEP} -delete
curl -s -X POST http://127.0.0.1:8000/internal/backup-report -d "status=ok&file=zdr_${DATE}.dump"
```

定时：`0 2 * * *` 执行数据库备份，`30 2 * * *` 执行文件备份。

### 7.3 恢复步骤

```bash
# 1 停止应用，避免写入
docker compose stop api web

# 2 校验备份完整性
sha256sum -c /opt/zdr/backup/db/zdr_20261109_0200.sha256

# 3 重建数据库
docker exec -i zdr-db psql -U postgres -c "DROP DATABASE IF EXISTS zdr;"
docker exec -i zdr-db psql -U postgres -c "CREATE DATABASE zdr OWNER zdr_app;"

# 4 恢复数据
docker exec -i zdr-db pg_restore -U zdr_app -d zdr --clean --if-exists \
    < /opt/zdr/backup/db/zdr_20261109_0200.dump

# 5 恢复文件
rsync -a /opt/zdr/backup/files/ /opt/zdr/data/files/

# 6 启动并验证
docker compose up -d api web
curl -k https://localhost/healthz
```

### 7.4 演练要求

每月执行一次恢复抽检（恢复至临时库，比对关键表行数）；每季度执行一次完整恢复演练（含应用启动与业务验证）。演练记录归档，作为等级保护测评证据。目标：恢复点目标不超过 5 分钟，恢复时间目标不超过 30 分钟。

## 10 升级与回滚

### 10.1 升级流程

```
① 变更申请：内容、影响范围、回滚方案、时间窗口
② 审批：政法委 + 技术负责人
③ 备份：数据库、文件、当前镜像标签
④ 预发验证：预发环境执行冒烟与关键用例
⑤ 生产部署：低峰期滚动更新应用节点，逐台替换
⑥ 验证：冒烟 + 关键业务抽查
⑦ 观察 30 分钟，确认无异常
⑧ 记录变更
```

### 10.2 数据库变更

所有结构变更通过迁移脚本执行，须向后兼容：先加列后使用、先双写后切读；破坏性变更（删列、改类型）分两次发布，第一次停止使用，第二次删除。每次迁移前执行数据库全量备份。

### 10.3 回滚

| 场景 | 操作 |
|---|---|
| 应用异常 | 切回上一镜像标签并重建容器 |
| 数据异常 | 停止应用、恢复备份、启动（30 分钟内） |
| 迁移失败 | 执行降级脚本回退版本，再恢复备份数据 |

**决策时限**：上线后 2 小时内出现严重问题直接回滚，不在生产环境调试。

## 11 故障处理手册

| 现象 | 可能原因 | 排查 | 处理 |
|---|---|---|---|
| 页面无法打开 | 代理未启动、证书过期 | 检查容器状态、证书有效期、443 端口 | 重启服务、更换证书 |
| 登录失败（账号正确） | 账号锁定、令牌密钥不一致 | 查登录审计记录、核对密钥配置 | 解锁、统一密钥 |
| 接口 500 | 应用异常 | 查应用日志堆栈与 trace_id | 修复或重启 |
| 数据库连不上 | 连接数满、磁盘满、进程退出 | 查数据库日志、磁盘使用、活动连接 | 清理连接、扩容、重启 |
| 导入超时 | 文件过大、单事务过长 | 查批次状态与处理日志 | 改异步、减小批次 |
| 导出文件为空 | 查询无结果、权限过滤 | 核对查询条件与数据范围 | 调整条件或授权 |
| 驾驶舱数据不更新 | 汇总任务失败 | 查任务日志 | 手动重跑任务 |
| 图表空白 | 地图数据未加载、接口失败 | 浏览器开发者工具查网络请求 | 检查资源与接口 |
| 大屏错位 | 分辨率不匹配 | 检查缩放设置 | 调整缩放参数 |
| 磁盘占满 | 日志或备份未清理 | 按目录统计占用 | 清理并调整保留策略 |
| 慢查询突增 | 索引失效、统计信息陈旧 | 执行计划分析、表统计 | 分析表、补索引 |
| 主备延迟 | 大事务、网络抖动 | 查复制状态 | 拆批、排查网络 |

## 12 应急预案

| 场景 | 响应措施 | 时限 | 责任 |
|---|---|---|---|
