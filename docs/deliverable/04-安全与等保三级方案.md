## 1 安全目标与总体思路

### 1.1 三类核心资产

| 资产 | 内容 | 泄露/破坏后果 |
|---|---|---|
| 人员敏感信息 | 身份证号、姓名、住址、联系方式、监护人信息 | 公民个人信息泄露，涉《个人信息保护法》责任 |
| 特殊类别信息 | 精神障碍诊断、邪教组织、涉访诉求、扬言内容、原罪名 | 政治敏感，可能引发舆情与人身安全风险 |
| 台账与统计结论 | 风险等级、双在册、多标关系、镇街分布 | 泄露管控底数与盲区，直接影响稳定工作 |

### 1.2 总体思路

1. **边界收窄**：系统部署于政务内网，无互联网入口、无互联网出向连接，从网络层阻断数据外流。
2. **权限收敛**：三级权限 + 字段级密级 + 数据范围，按岗位授予最小必要。
3. **全程留痕**：查询、查看、变更、导出、授权全链路审计，日志不可篡改。
4. **默认脱敏**：界面默认掩码，明文需审批授权并限时。
5. **三权分立**：系统管理员、安全管理员、安全审计员职责分离，互相制约。
6. **测评前置**：Demo 阶段即按三级要求实现关键控制点，避免正式期集中返工。

## 2 安全技术体系（等保三级技术要求落地）

### 2.1 安全物理环境

由区政务云机房承担，本系统提出要求并索取证明：

| 控制点 | 要求 | 落地方式 | 证据 |
|---|---|---|---|
| 物理位置选择 | 机房抗震、防风、防雨、防潮 | 政务云机房资质 | 机房等级证明 |
| 物理访问控制 | 出入口专人值守、电子门禁 | 政务云 | 出入记录制度 |
| 防盗窃破坏 | 设备固定、介质管理 | 政务云 | 巡检记录 |
| 防雷击/防火/防水防潮 | 消防、漏水检测 | 政务云 | 检测报告 |
| 温湿度控制 | 精密空调 | 政务云 | 监控数据 |
| 电力供应 | 双路市电 + UPS | 政务云 | 供电方案 |
| 电磁防护 | 接地、屏蔽 | 政务云 | 检测报告 |

> 本项目自身不建设机房，安全性依托政务云，需在测评时提供云平台等保测评报告与责任边界说明。

### 2.2 安全通信网络

| 控制点 | 本项目措施 |
|---|---|
| 网络架构 | 划分应用区、数据区、管理区；应用与数据库间经安全组策略限制，仅开放业务端口 |
| 通信传输 | 全站 HTTPS（TLS 1.2+，优先国密 TLS）；禁用弱套件与 SSLv3/TLS1.0/1.1 |
| 带宽与冗余 | 核心链路冗余由政务云提供 |
| 可信验证 | 服务器启动完整性校验（政务云提供），应用侧校验发布包签名 |

### 2.3 安全区域边界

| 控制点 | 本项目措施 |
|---|---|
| 边界防护 | 政务云边界防火墙 + WAF；仅开放 443，管理端口（22/数据库端口）不对业务网段开放 |
| 访问控制 | 按 IP 段 + 账号双控；公安、信访、卫健、司法各端口仅允许本部门网段访问对应功能 |
| 入侵防范 | WAF 规则库开启，防 SQL 注入、XSS、命令执行；对异常高频查询告警 |
| 恶意代码防范 | 服务器部署主机防护 Agent（政务云统一）；上传文件做类型白名单与病毒扫描 |
| 安全审计 | 边界设备日志接入日志审计平台，留存 ≥6 个月 |

**关键设计：出向连接白名单**
- 应用服务器出向仅允许访问数据库、文件存储、内部模型服务；
- 默认拒绝一切互联网出向（无 DNS 外联、无外网 NTP、无外部 CDN）；
- 前端构建产物全部本地化，不引用外部字体/JS/CSS；
- 该策略在部署时以 iptables/安全组显式配置，并提供配置截图作为测评证据。

### 2.4 安全计算环境

| 控制点 | 本项目措施 |
|---|---|
| 身份鉴别 | 账号唯一；口令 ≥8 位且含大小写数字符号，90 天更换，不得与前 5 次重复；连续 5 次失败锁定 10 分钟；**管理员与明文导出操作启用双因子**（口令 + 短信/OTP，正式期接政务 CA） |
| 访问控制 | RBAC + 数据范围 + 字段密级三层；默认拒绝；权限变更留痕；及时清理离岗账号（每月核对） |
| 安全审计 | 覆盖每个用户，记录时间/用户/事件类型/结果/对象；审计记录不可删除、不可修改；留存 ≥6 个月；审计员独立账号 |
| 入侵防范 | 最小安装原则（仅必要组件）；关闭无用端口与服务；定期漏洞扫描；高危漏洞 7 日内修复，中危 30 日 |
| 恶意代码防范 | 主机防护 + 上传文件扫描；禁止在服务器安装非授权软件 |
| 可信验证 | 发布包哈希校验；镜像签名 |
| 数据完整性 | 关键业务表（person/person_tag/risk_change/audit_log）使用触发器记录变更前后值；备份文件校验和 |
| 数据保密性 | 身份证号、手机号、监护人信息应用层加密存储（SM4/AES-256-GCM）；密钥独立管理；备份介质加密 |
| 数据备份恢复 | 每日全量 + 每小时增量（WAL 归档）；保留 30 天；每周一次恢复演练抽检；异地/离线备份一份 |
| 剩余信息保护 | 账号注销后清除其会话与缓存；存储介质报废前消磁/物理销毁并登记 |
| 个人信息保护 | 仅采集最小必要字段；界面默认脱敏；明文访问需审批；不向第三方提供；不用于业务外用途 |

### 2.5 安全管理中心

| 控制点 | 本项目措施 |
|---|---|
| 系统管理 | 系统管理员负责账号、配置、备份，**不授予业务数据查看权限** |
| 审计管理 | 安全审计员独立账号，仅可查日志、不可改数据、不可删日志；审计员不参与业务运维 |
| 安全管理 | 安全管理员负责角色与权限分配、安全策略配置，不进行系统运维 |
| 集中管控 | 日志统一汇聚至日志审计平台；监控告警统一至运维平台；补丁与病毒库集中管理 |

| 角色 | 可授予系统管理 | 可授予安全管理 | 可授予审计管理 | 可查看业务明细 |
|---|---|---|---|---|
| 系统管理员 | ✓ | ✗ | ✗ | ✗ |
| 安全管理员 | ✗ | ✓ | ✗ | ✗ |
| 安全审计员 | ✗ | ✗ | ✓ | ✗ |

由不同自然人担任，账号不得共用，权限不得交叉。

## 3 数据不出域边界

### 3.1 五条边界

| 边界 | 具体要求 | 技术落实 |
|---|---|---|
| 网络边界 | 系统无互联网入口与出向 | 安全组默认拒绝出向；部署后做连通性验证并留证 |
| 模型边界 | 实名数据不进入任何外部大模型接口 | 不配置任何外部 API Key；本地模型与业务同域；代码层禁止外呼（出口代理白名单 + 静态扫描） |
| 运维边界 | 远程运维须审批、经堡垒机、全程录屏 | 堡垒机接入；临时账号限时；运维操作双人见证（高危） |
| 介质边界 | 数据交换使用加密移动介质并登记 | U 盘白名单 + 加密；导入导出登记台账 |
| 展示边界 | 大屏、Pad 展示不含明文敏感字段 | 大屏账号强制 L1 视图；Pad 端禁用水印移除 |

### 3.2 数据交换安全（Demo 阶段的关键动作）

会议约定由政府通过安全渠道（U 盘或内部群）提供脱敏表头与样例。执行要求：

1. 提供方先行脱敏：去除身份证号中间 8 位、手机号中间 4 位、姓名保留姓、住址去除门牌；
2. 接收方在隔离终端接收，落地前做病毒扫描；
3. 接收记录登记：时间、提供人、文件清单、用途、接收人；
4. **Demo 环境严禁存放真实人员全量数据**，样例数据使用后按约定销毁或转入隔离库。

## 4 数据安全专项

### 4.1 数据分类分级

| 级别 | 数据内容 | 保护要求 |
|---|---|---|
| 核心数据 | 全量实名台账、特殊类别明细 | 加密存储、严格授权、禁止导出明文（除审批） |
| 重要数据 | 统计结果、镇街分布、风险结构 | 授权访问，导出留痕 |
| 一般数据 | 字典、组织架构、日志元数据 | 常规访问控制 |

### 4.2 全生命周期管控

| 阶段 | 措施 |
|---|---|
| 采集 | 最小必要；明确采集目的与依据；由部门提供而非系统主动抓取 |
| 传输 | HTTPS/国密；文件交换加密压缩 + 独立口令 |
| 存储 | 敏感字段加密；数据库账号最小权限；表空间与备份分离 |
| 使用 | 默认脱敏；明文审批；水印（账号+时间）；禁止截屏外传（管理制度约束 + 终端管控） |
| 共享 | 仅向政法委、四部门按职责共享；不向第三方；共享留痕 |
| 导出 | 审批 + 双人复核（>50 条）+ 生成水印 + 流水登记 |
| 归档 | 消减人员档案归档保留，不物理删除；归档库单独授权 |
| 销毁 | 到期数据经审批后销毁并登记；介质物理销毁 |

### 4.3 个人信息保护合规要点

1. 处理敏感个人信息（行踪轨迹、健康医疗、犯罪记录、宗教信仰相关）需具备明确法定职责依据，由政法委统筹确认处理合法性基础；
2. 系统内提供"个人信息处理告知"页，说明处理目的、范围、保存期限、责任部门；
3. 建立个人权利响应流程（查询、更正、删除申请），由主管部门受理并在 15 个工作日内答复；
4. 不进行自动化决策定级——风险等级调整必须人工审批，AI 仅作提示（避免《个人信息保护法》第 24 条自动化决策合规风险）；
5. 委托处理（智谱/华企盾作为技术方）需签订数据处理协议，明确处理范围、安全措施、保密义务、违约与审计权。

## 5 密码应用方案

| 场景 | 密码技术 | 说明 |
|---|---|---|
| 传输加密 | 国密 TLS（SM2/SM3/SM4 套件）或 TLS1.2+ | 优先国密，需政务云网关支持 |
| 存储加密 | SM4 或 AES-256-GCM | 身份证、手机号、监护人信息 |
| 身份鉴别 | 口令 + OTP/短信；正式期接政务 CA 数字证书 | 管理员与明文导出强制双因子 |
| 完整性 | SM3/HMAC-SHA256 | 关键表变更、备份文件、发布包 |
| 密钥管理 | 独立密钥管理模块，密钥不与密文同库 | 密钥分级：主密钥（离线保管）/ 数据密钥（定期轮换） |

**过渡说明**：Demo 阶段以 TLS + AES 满足基本要求；正式期按 GB/T 39786 第三级开展密码应用安全性评估（密评），如需国密改造在建设期完成。

| 类别 | 需建立的制度 | 责任方 |
|---|---|---|

## 7 安全事件应急

| 场景 | 响应动作 | 时限 |
|---|---|---|
| 发现异常批量查询/导出 | 立即冻结账号，追溯审计日志，通报政法委 | 30 分钟内 |
| 数据疑似泄露 | 断网隔离、保全证据、启动调查、按程序上报网信/公安 | 1 小时内上报 |
| 账号被盗用 | 强制下线、重置口令、核查操作记录 | 即时 |
| 勒索病毒/入侵 | 隔离主机、从备份恢复、漏洞根除后复测 | 4 小时内恢复业务 |
| 备份不可用 | 启用异地备份，重建数据库 | 8 小时内 |

**演练要求**：每年至少一次数据泄露应急演练与一次备份恢复演练，形成演练报告。

### 8.2 Demo 阶段即需具备的 8 项

避免正式期返工，以下 8 项在 Demo 版本就要做对：

1. 三员账号分离（三个独立账号，权限互斥）；
2. 登录失败锁定 + 口令复杂度；
3. 全量操作审计（含查看档案、导出），日志表禁止 UPDATE/DELETE；
4. 前端无外部资源引用，后端无互联网出向；
5. 敏感字段加密存储 + 界面默认掩码；
6. 导出审批留痕 + 水印；
7. 数据库每日备份任务已配置；
8. HTTPS 已启用，HTTP 强制跳转。

## 10 风险提示（需政府侧决策）

| 事项 | 说明 | 建议 |
|---|---|---|
| 定级结论 | 本系统处理敏感个人信息且涉及维稳业务，建议定三级；若定二级将无法通过后续合规审查 | 尽早启动定级备案 |
| 备案主体 | 系统属政法委业务系统，备案主体应为区委政法委 | 明确责任单位 |
| 数据合法性基础 | 敏感个人信息处理需明确法定职责依据 | 由政法委出具说明 |
| 测评时间 | 三级测评通常需 2—3 个月，含整改 | 与建设期并行，不留到上线前 |
| 云平台责任边界 | 政务云 IaaS 层安全责任需书面划分 | 与政务云运营方签署责任边界文件 |
