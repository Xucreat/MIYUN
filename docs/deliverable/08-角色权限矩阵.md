## 1 设计原则

| 原则 | 说明 |
|---|---|
| 三层控制 | 功能权限（能不能进/能不能点）+ 数据范围（能看哪些行）+ 字段密级（能看哪些列），三层独立配置，缺一层就有漏洞 |
| 默认拒绝 | 未显式授权的功能与数据一律不可见 |
| 最小必要 | 按岗位职责授权，不按行政级别"一刀切" |
| 服务端强制 | 所有控制在后端生效，前端只做展示收敛；前端隐藏不等于安全 |
| 三权分立 | 系统管理、安全管理、审计管理由不同人担任，权限互斥 |
| 全程留痕 | 权限变更、授权使用、越权尝试全部记录 |

## 4 数据范围矩阵

### 4.1 范围类型

| 类型 | 定义 | 实现 |
|---|---|---|
| ALL | 全区全部在册人员 | 无过滤条件 |
| DEPT | 本部门来源的标签所关联的人员 | `EXISTS (tag WHERE source_dept = :dept)` |
| STREET | 责任镇街 ∈ 授权镇街集合 | `street_code IN (:streets)` |
| STREET_AND_DEPT | 本镇街且本部门 | 两者交集 |
| NONE | 无业务数据权限 | 强制返回空 |

### 4.2 矩阵

| 角色 | 人员数据范围 | 走访记录 | 预警 | 统计口径 |

| R2 政法委主管 | ALL（全字段） | 全部读写 | 全部 | 全区 |

| R4 部门经办 | DEPT | 本部门 | 本部门 | 本部门 |
| R5 属地经办 | STREET | 本辖区 | 本辖区 | 本辖区 |
| R6 属地负责人 | STREET | 本辖区 | 本辖区 | 本辖区 |

### 4.3 边界情形

| 情形 | 规则 |
|---|---|
| R3 部门主管能否看到其他部门的人？ | 能看到"该人员存在"（因为在自己部门的台账里），但其他部门的标签内容按字段权限控制 |
| R5 属地经办能否看到非本辖区但住在本辖区的人？ | 以 `street_code`（责任镇街）为准，不看现住址，避免责任错位 |

| 已消减人员 | 默认不在范围内，仅 R2/R3 可通过 `person:list:reduced` 查看 |
| 大屏账号 | 固定使用专用大屏账号（R1 视图 + `dashboard:bigscreen`），不绑定具体领导个人账号 |

## 6 特殊场景权限

### 6.1 明文查看与导出

| 步骤 | 规则 |
|---|---|
| 申请 | 填写：人员范围（可多选）、用途、有效期（默认 24h，最长 72h） |
| 审批 | R2 审批；单次 >50 条或涉未成年人时需第二个审批人 |
| 生效 | 生成临时授权令牌，仅对本人、指定 IP 段、有效期内生效 |
| 使用 | 每次明文访问写审计（谁、何时、看了谁、用途、审批单号） |
| 失效 | 到期自动失效；可提前撤回 |
| 留痕 | 导出文件加隐形水印（账号 + 时间戳），便于追溯泄露源 |

### 6.2 涉未成年人

- 访问日志单独标记，每月由审计员专项审查；
- 导出需额外审批（`export:minor`）；
- 界面显示"涉未成年人"标签，提醒经办人注意保护。

### 6.3 已消减人员

- 默认过滤掉，仅 `person:list:reduced` 权限可查；
- 查看需二次确认弹窗，说明用途；
- 批量导出禁止。

### 6.4 大屏与 Pad

- 使用专用设备账号，仅 R1 视图 + `dashboard:bigscreen`；
- 屏蔽所有导出、下钻到个人档案的操作；
- 无人值守时自动锁屏（5 分钟无操作）；
- 大屏数据只到镇街级，不显示到社区门牌。

### 6.5 接口调用（为后续对接预留）

- 对外接口使用独立的服务账号，仅有特定接口权限；
- 接口级白名单 + 签名 + IP 限制；
- 接口调用量单独审计与限流。

## 7 权限实现机制

### 7.1 后端实现

```
请求 → 认证中间件（JWT 解析，注入 CurrentUser）
     → 权限依赖（Depends(require_perm("person:update"))）
     → Service 层
     → Repository 层：QueryScope 自动注入数据范围 WHERE
     → 序列化层：按字段密级输出明文/掩码/剔除
```

关键实现要点：

1. **权限装饰器**：`@require_perm("export:plain")`，未授权返回 403 + 中文提示；
2. **QueryScope 单点注入**：所有 list 查询必须显式接收 `scope: QueryScope` 参数，Repository 基类统一拼接条件。**不允许在业务代码里手写权限过滤**；
3. **序列化脱敏**：Pydantic 模型定义 `masking_rules`，输出时按 `current_user.role_clearance` 处理，页面无感知；
4. **越权记录**：403 响应写审计日志（`result=denied`），连续 5 次触发告警。

### 7.2 前端实现

1. 路由守卫：登录后拉取权限码集合，未授权路由不注册（404 而非 403，避免暴露菜单结构）；
2. 按钮级：`v-perm="'person:export:plain'"`，无权限不渲染；
3. 字段级：统一 `<MaskedText>` 组件，掩码规则由后端返回（前端不硬编码），避免前后端规则不一致；
4. 不做安全依赖：前端所有隐藏都是"体验优化"，安全由后端保证。

## 8 权限运维

| 事项 | 规则 |
|---|---|
| 开户 | 由用人单位提交《账号开通申请单》，安全管理员创建，系统管理员配置组织 |
| 授权 | 按角色模板授权，个别调整需说明理由；授权记录留痕 |
| 变更 | 岗位变动 3 个工作日内调整权限 |
| 离岗回收 | 人事通知后 1 个工作日内停用账号；保留账号 90 天审计追溯后归档 |
| 定期复核 | 每季度由安全管理员出具权限清单，各部门确认；每年一次全面复核 |
| 长期未用 | 90 天未登录自动停用，需重新激活 |
| 共享账号 | 严禁；发现即停用并通报 |
