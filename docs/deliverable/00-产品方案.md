## 1 建设背景

区委政法委组织区公安分局、区信访办、区卫健委、区司法局等行业主管部门，对全区重点人员完成全面起底。经身份标签比对查重，全区重点人员归并为 11 类、约 6000 人，呈现三个特征：

**一是台账分散。** 11 类人员分属四个部门管理，台账格式各异。经对四部门脱敏表头逐项核对，15 份台账、485 个字段位、253 个不同字段名，其中跨部门同名可用字段仅 7 个，字段一致率不足 3%。同一概念在不同部门有 4 至 11 种叫法，同一人员在不同台账中存在多套记录，无法形成全区统一的底数。

**二是盲区集中。** 存在两类高风险群体：双在册人员（公安卫健双在册严重精神障碍患者、公安信访双在册涉访人员）与多重身份标签人员。前者由两个部门共同管理，责任界面容易模糊；后者标签多、隐患杂、风险维度叠加，任何单一部门视角都无法看到全貌，易出现"都管一点、都不全管"。

**三是动态不足。** 现有台账以月度为周期人工汇总，风险等级调整、人员增减、走访落实依赖报表流转，难以支撑重点时期的快速响应与"每日见面、每日零报告"的闭环管理。

面对 2027 年安全稳定形势要求，需要建立一套覆盖全区的重点风险人员实名制台账管理与风险预警系统，实现底数清、情况明、动态准、管得住。

| 责任实 | 每名人员对应责任单位、责任民警或包联干部；查询、变更、导出全程留痕，可追溯至人到时刻 |

## 3 产品定位与总体思路

### 3.1 产品定位

本系统是**区级重点人员管控的行政台账与研判支撑平台**，承担四部门台账的汇聚、归一、分级、监测与督办职能。

与公安专业业务系统的关系是分工协同：公安系统基于行为数据开展专业研判与打击处置，本系统基于部门报送的台账开展行政管控与责任落实。本系统接收公安给出的重点关注结论，不获取其原始行为数据，二者在数据来源、业务环节、责任主体上边界清晰、互为补充。

### 3.2 总体思路

**以人为核心组织数据，以等级为标尺统一口径，以责任为闭环落实管控。**

具体展开为四条主线：

| 主线 | 内容 | 解决的问题 |
|---|---|---|
| 人 | 身份证号为唯一键，一份档案对应一个自然人 | 一人多档、底数不清 |
| 档 | 类别标签可叠加，各标签保留部门原始判断 | 标签重合、口径冲突 |
| 事 | 走访、沟通、研判、调整全程记录 | 管控过程无痕迹 |
| 责 | 责任单位、责任人、包联关系明确到人 | 责任悬空、追责无据 |

四条主线构成人员档案的四个维度，替代传统以外部数据源为中心的建设方式，聚焦管控责任本身。

## 5 功能特性

**全息档案。** 以身份证号为唯一键建立人员主档，一个自然人一份档案；支持多部门台账自动查重并档，同一人员可叠加多个类别标签，各标签保留部门原始等级判断，同时按"就高不就低"生成区级管控等级，档案同时呈现部门视角与区级标准。

**态势分析。** 全域人员总量、风险层级、类别结构、镇街分布、变化趋势一屏呈现；地图按镇街渲染人员密度并支持下钻，图表与明细双向联动，任一指标可追溯至具体人员清单。

**风险分级。** 建立跨部门的统一风险序，将公安高中低风险、信访 A/B/C 类、邪教一二三级、卫健高中低风险、司法重点一般等不同口径映射至同一标尺，实现跨类别比较、统一筛选与一致统计，部门原值完整保留。

**智能预警。** 内置走访超期、失访拒访、未定级超期、双在册未确认、降级后无随访、依据缺失、未指定包联七类规则，自动生成待办并指派至责任人，处置过程闭环留痕，主动暴露"该管未管"的漏洞。

**协同管控。** 双在册人员生成双部门确认任务，任一方未确认即进入待办；走访任务按响应等级自动下发；重点时期自动生成应见名单，属地回填见面情况后自动核算"应见未见"清单。

**数据治理。** 支持四部门 15 类台账的直接导入，通过表块识别、列位映射、同义转换、合并列拆分、质量校验五步完成归一，导入过程生成批次报告，原始表全量留档可回溯。

**查询统计。** 支持姓名、身份证号、类别、等级、镇街、责任人、走访状态等条件组合检索，支持标签交集、差集、仅含三类集合运算与拼音检索，查询结果按权限自动脱敏，导出留痕并加盖水印。

**全程留痕。** 登录、查询、查阅档案、修改信息、调整等级、导出数据全部记录；等级变动与档案变更保留前后值；审计日志只增不改、不可删除，留存不少于六个月。

## 6 特色优势

### 6.1 以人为轴、多标归并，解决一人多档

传统做法按部门建表，同一自然人可能在不同台账中出现多次，既重复统计又形成管理真空。本系统以身份证号为主键横向打通四部门数据，一个自然人只保留一份主档，多个类别以标签形式叠加，标签数量、双在册关系自动计算。既能回答"全区多少人"，也能回答"这个人被几个部门管、按谁的等级管"。

### 6.2 多源归一、口径可比，解决标准不一

四部门 253 个字段名、8 套风险分级体系、11 种类别叫法，直接汇总必然失真。本系统通过主干字段统一、类别字段扩展、原始字段留存的三层模型，用 22 个主干字段承载全部共有信息，其余按类别挂载或原样留档；通过统一风险序把 8 套分级映射到同一标尺。归一过程不改变部门原有报表习惯，也不要求部门返工重填。

### 6.3 分级分类、精准定位，解决盲区漏管

管控的重点不在人多的类别，而在标签叠加、部门交叉的人群。系统按标签数量、部门交叉关系、风险层级三个维度自动识别重点关注对象，将双在册、三重标签、待核实三类人群单列呈现，并按"就高不就低"统一管控标准，避免出现某一部门评定为低风险而整体措施随之下降的情况。

## 7 应用价值

**建档环节。** 四部门台账一次导入即完成建档、查重、并档、标识，替代原先跨部门人工比对，月度汇总周期由数日缩短至小时级。

**定级环节。** 等级调整有依据、有流程、有留痕，等级变动形成月度台账，管控标准的确定过程可核查、可追责。

**预警环节。** 管控漏洞从事后追责转为事前提醒，走访超期、失联失访、依据缺失等情形自动暴露，责任单位在问题发生前即收到待办。

**处置环节。** 走访、沟通、研判、处置全过程记录在案，重点时期见面情况闭环回填，应见未见清单自动生成，管控措施落实情况可量化考核。

**决策环节。** 全域态势、结构分布、变化趋势为研判部署提供数据支撑，重点时期名单可快速圈选下发，管控资源投放有据可依。

整体上，系统推动重点人员管控由分散台账、人工汇总、被动响应，转向统一底数、动态更新、主动预警，实现管控方式从粗放式向精细化转变。

## 9 技术实现

| 层次 | 技术构成 |
|---|---|
| 前端 | Vue 3 + TypeScript + Vite，Element Plus 组件库，ECharts 图表与行政区划渲染 |
| 后端 | Python FastAPI + SQLAlchemy 2.0，模块化单体架构，REST 接口 |
| 数据库 | PostgreSQL 16，JSONB 承载类别扩展字段，分区表承载审计日志 |
| 检索 | 库内索引 + 三元组模糊匹配 + 拼音索引，6000 人规模毫秒级响应 |
| AI 能力 | 本地部署大模型，用于走访记录摘要与涉稳关键词提示，结论仅作辅助，不参与自动定级 |
| 部署 | 容器化部署，支持单机与双机两种形态，适配国产操作系统与国产数据库 |
| 地图 | 本地行政区划矢量数据渲染，具备审图号，不依赖外部地图服务 |

**关键取舍**：一期不引入微服务、消息队列、分布式缓存与外部搜索引擎。现有数据规模（6000 人、百万级日志）由单套 PostgreSQL 即可支撑，减少组件即减少测评对象、运维负担与故障面，同时为后续扩展保留清晰边界。

## 10 安全与合规

| 维度 | 措施 |
|---|---|
| 等级保护 | 按网络安全等级保护第三级要求设计，覆盖物理、网络、边界、计算环境、管理中心五个技术层面与五项管理要求 |
| 数据不出域 | 系统部署于政务内网，无互联网入口与出向连接；实名数据不进入任何外部模型接口；地图、字体、脚本等资源全部本地化 |
| 分级授权 | 业务角色与系统角色分离，系统管理、安全管理、审计管理三员分立、权限互斥；数据权限与字段密级双重控制 |
| 最小必要 | 敏感字段加密存储，界面默认脱敏，明文查看与导出须经申请审批并限时生效 |
| 全程留痕 | 查询、查阅、变更、导出全过程审计，日志不可修改删除，留存不少于六个月 |
| 个人信息保护 | 明确处理目的与范围，仅采集管理必需字段，不进行自动化决策定级，等级调整一律人工审批 |
| 备份容灾 | 每日全量加持续增量备份，定期恢复演练，目标 RPO 不超过 5 分钟、RTO 不超过 30 分钟 |

| 底数 | 分散在四部门 15 份台账，格式各异，字段一致率不足 3% | 一套档案库，6028 人一人一档，22 个主干字段统一 |
| 汇总 | 月度人工报表流转，周期数日 | 台账导入即完成归并与统计，小时级 |
| 风险识别 | 依赖人工比对标签与部门交叉关系 | 双在册、多重标签、待核实三类盲区自动识别并置标识 |
| 管控标准 | 各部门按本部门等级落实，标准不一 | 就高不就低，一人一标准，标准来源可查 |
| 过程管理 | 走访与沟通记录分散，落实难以量化 | 走访登记、见面回填、应见未见核算全流程闭环 |
| 责任落实 | 追责需跨部门调取材料 | 查询、变更、导出全程留痕，可追溯至人与时刻 |
| 重点时期 | 名单人工汇总下发，回填靠报表 | 名单条件圈选一键下发，见面情况实时回填与核算 |

系统建成后，全区重点人员管控形成"一套标准、一本台账、一张态势图、一条责任链"，为 2027 年安全稳定工作提供数据支撑与管理抓手，并为后续社会治安综合治理平台建设奠定数据与标准基础。
