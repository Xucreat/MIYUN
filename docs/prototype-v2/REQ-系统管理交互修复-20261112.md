## 0. 共性根因（一次修复，解决 8 处「点按钮跳空白」）

`system.html:992`

```js
var btns = document.querySelectorAll("#sysNav button");   // ← 过宽
```

`#sysNav` 下的 `button` 不只是 4 个页签，还包含右侧操作组的 11 个动作按钮。
点击「新建账号 / 权限清单导出 / 角色模板 / 导出字典包 / 新增字典项 / 保存草稿 / 提交发布 / 完整性校验 / 导出日志 / 生成审计报告」时：

1. 该按钮被当成页签 → `go(b.dataset.tab)` = `go(undefined)`；
2. `panels.forEach(p => p.style.display = p.dataset.panel === undefined ? "" : "none")` → **四个面板全部 `display:none`**；
3. `acts` 分组同时被全部隐藏 → 内容区整片空白。

修复方式：选择器收窄为 `#sysNav button[data-tab]`（1 行），再为各按钮补真实行为（明细见后）。

> 说明：这批按钮目前**没有任何点击后逻辑**，`page` 变空白即上述根因所致，不是浏览器默认提交行为（全页无 `<form>`）。

## 5. 答疑（用户提出、需当场回答的两处）

**A.「日志完整性」是什么意思、对政法委主管有用吗？**
它是「审计日志防篡改」的自证机制：每条日志带前一条的哈希，逐条串成链，任何一条被改/被删都会导致后续哈希对不上，校验即报差异。所以它证明的是「日志可信、可作追责依据」，而不是业务功能。
对政法委主管（业务管理角色）而言：日常用不到操作入口，但**结论有用**——导出留痕、越权拦截、明文访问都要靠它背书。建议按角色差异化：R9 安全审计员看校验动作与报告；R2 政法委主管只看「最近校验时间 / 结果 / 差异数」结论，按钮置灰并提示归口。

**B.「等级调整审批路由」是什么意思、与「审批页」什么关系？**
它是「按目标风险等级决定谁来批、批多久」的规则表：调为 1 级要过 4 道（部门主管 → 属地负责人 → 政法委主管 → 区级确认，3 日），2 级 2 道（5 日），3 级部门内闭环（7 日），4 级属地内闭环（7 日）。
「审批页 ›」跳到 `risk.html`（等级调整审批）——那张表就是该页审批单生成审批链的依据。现状两处节点名不一致（risk 页为「属地提交 → 部门主管 → 政法委审核 → 生效留痕」），建议统一（决策 D）。
