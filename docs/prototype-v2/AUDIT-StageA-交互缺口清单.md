# 阶段 A · 原型交互缺口全量清单（只读审计）

- 审计对象：`docs/prototype-v2/`（14 个 HTML + `assets/app.css` + `assets/shell.js`）
- 审计方式：逐文件静态阅读（DOM / 事件绑定 / URL 参数 / 数据硬编码），未修改任何文件
- 审计时间：2026-11-10
- 目标基线：可完整演示的 Demo —— 完整演示数据 + 完整页面间流转 + 主操作闭环（跳转 / 筛选 / 详情 / 确认弹窗 / 提交反馈）

## 一、结论先行

1. **页面骨架与视觉已达标，可交互面积约 15%。** 全站 14 个页面中，真正带页面级脚本的只有 8 个；`alerts / analytics / import / person / risk / wartime` **6 个页面除统一外壳外零 JS**，其中 `alerts`（预警处置）、`risk`（等级调整审批）、`import`（数据导入）三页恰好是 06 演示脚本里"讲得最重"的三段。
2. **已跑通的三处，质量很高**，可作为阶段 B 的实现范式：`dashboard.html` 地图二级下钻 + 下钻弹窗、`persons.html` 与 `system.html` 的标签切换（含 URL 同步）、`blind.html` 的三类盲区表切换（含命中数联动）。
3. **最大风险不是"按钮没响应"，而是"跨页只到页面级、到不了对象级"。** 全站只有 5 处 URL 参数（`dashboard?street/community`、`persons?tab`、`board?tab`、`system?tab`），所有"查看档案""处理""督办"链接都指向同一个 `person.html`（永远显示任玉荣），一旦演示时被追问"点进去是这个人的吗"，链路立刻破功。
4. **还缺一层全站基础设施**：没有统一的提示条（toast）、通用确认弹窗、伪下拉组件。`dashboard` 的弹窗是本页私有 `.mask-bg`，其它页无弹窗能力 —— 这直接导致"确认弹窗 + 提交反馈"无处落地。
5. **数字化结论**：27 处 `href="#"`（点了会跳到页顶，观感等同坏链）；约 60 个 `.select` 伪下拉（div 模拟）无任何点击行为；约 100 项交互缺口，其中**阻断演示动线的 21 项**必须做，其余可按优先级排。

> 我的判断：**阶段 B 应用"补基础设施 + 数据驱动 + 演示动线打穿"的方式做，而不是逐页补 onclick。** 后者的结果是 100 个散装 handler，越改越乱；前者是把 `assets/` 扩展成 `ui.js`（组件层）+ `data.js`（演示数据层）+ `store.js`（会话状态层），各页只负责"渲染 + 绑定业务动作"。

## 六、阶段 B 技术方案（建议）

### 6.1 目录与分层

```
assets/
  app.css      ← 只增不改：补 toast / modal / dropdown / drawer 样式
  shell.js     ← 补：顶栏搜索、通知过滤、帮助面板、徽标改由数据层供给
  data.js      ← 新增：唯一演示数据源
  store.js     ← 新增：sessionStorage 会话状态（处置/审批/导入/导出流水/已选）
  ui.js        ← 新增：Toast / Confirm / Modal / Drawer / Select / Checkbox / Seg / Chips / Pager / sortTable
  demo.js      ← 新增：演示动线剧本（可选，一键走完 0—11 环节）
```

### 6.2 关键约束

1. **单一数据源**：所有页面数字来自 `data.js`（6,028 / 486 / 1,704 / 3,226 / 612 / 127 / 214 / 358 / 412-368-44 / 19↑27↓ / 20 镇街 / 7,112 人次），页面只做格式化，不再手写常量 → 从根上解决"页面之间不打架"。
2. **状态可累积**：`store.js` 用 sessionStorage，处置一条预警、通过一项审批后，刷新不回滚、跨页可见（驾驶舱计数、侧栏徽标、"已办"列表同步）。
3. **对象级 URL**：统一 `?id=`（人员）、`?code=`（预警/单号）、`?app=`（审批单）、`?street=`（镇街）、`?type=`（盲区类型）、`?view=`（快捷视图），保证任何"进详情"都能回到具体人/单据。
4. **反馈三件套**：所有提交类操作必须走「确认弹窗 → 进度/禁用态 → toast + 状态回落」，不允许裸按钮。
5. **不改视觉**：只补交互与状态，`app.css` 既有令牌与版式不动、页面结构不重排，避免已确认的视觉基线被打回。

### 6.3 建议拆成 4 个可验收批次

| 批次 | 内容 | 验收 |
|---|---|---|
| B1（基建） | `data.js` + `store.js` + `ui.js` + 27 处空链修复 + 顶栏搜索 | 任意页按 F5 数据一致；空链点击不再跳页顶 |
| B2（三段主流程） | alerts 处置闭环、risk 审批闭环、import 导入五步 | 每条流程走完，计数与"已办"同步 |
| B3（查询与下钻） | persons 列表筛选/勾选/分页/导出 + 组合查询语义联动 + dashboard 区间切换与下钻 + blind 核查任务 | 从驾驶舱点 486 → 台账 → 档案 → 回列表，全链路带参数 |
| B4（收尾） | system 规则可配置 + 账号/字典/审计动作 + postwar 督办 + board 自定义看板 + analytics 排序 + bigscreen 轮播 | 动线 0—11 一次性彩排通过 |
