## 二、A. 账号与角色

### A1　新建账号「单位」→ 下拉

- 现状：自由文本，无约束，可填任意值，与字典「责任部门」「行政区划·镇街」无关联。
- 改法：改为 `U.select` 下拉，选项按分组呈现——
  - **区级部门**：取自字典 `dept`（责任部门 94 条，含区级 + 3 成员单位 + 2 支撑）
  - **街镇**：取自字典 `town`（20 个镇街）
- 联动：选中后，若角色数据范围为空则按所选单位自动带出建议范围（已有 `scopeOf` 逻辑，仅扩数据源）。
- 影响：`openAcctNew()` 一处。

### A2　三员分立校验卡

- 现状：`#trioBody` 内含 5 行校验 + 2 行统计 + 分隔线 + 「生成本季度权限清单」按钮，整块一起滚动，按钮会随内容滚走。
- 改法：
  - 按钮移出 `#trioBody`，放入卡片底部固定区（`card-ft`），始终可见；
  - `#trioBody` 独立上下滚动，滚动阴影提示（复用规则与参数页已有做法）；
  - 卡片底部一行显示：`9 个角色 · 47 个账号 · 无冲突`（现 `#trioFoot` 内容）+ 按钮。
- 影响：`system.html` 该卡结构 + `renderTrio()` 去掉按钮拼接、单独绑定。

## 三、B. 数据字典

### B1 / B4　编辑 / 新增字典项的字段类型

| 字段 | 现状 | 改为 |
|---|---|---|
| 归属部门 | 自由文本 | 下拉，取 `dept` 字典（按 区级 / 成员单位 / 支撑 分组） |
| 可对应等级 | 自由文本「1 / 3」需手敲 | 多选标签，1—4 档（复用风险序 pill 样式） |
| 最近变更 | 自由文本日期，可乱填 | **见下方说明与待确认项** |
| 状态 | 已是下拉 | 不变 |

**「最近变更」是什么、有没有用？**

- 含义：该字典项最后一次被修改的日期。作用是判断这条口径是否过期（如"2026-04-08 之后没动过"）。
- 现状问题：作为**手填字段**没有意义——谁都能改，改了也不代表真变更；而真正的变更时间审计日志里已精确到秒。
- 建议：**表单里删掉这个字段**（新增/编辑都不出现），改为保存时由系统自动写入当天日期；**表格列保留**（这条信息对业务有价值）。这样既不会填错，也不丢信息。

### B2　「部门原等级 → 统一风险序 映射」卡占满

- 实测：卡片高 350px，内容区 274px，表格仅 158px → **表格下方空白 116px**。
- 原因是 4 行数据固定 26px/行，不随卡片高度伸展。
- 改法：
  - 表格 `height:100%`，4 行等分撑满内容区（每行约 55px），文字垂直居中；
  - 列宽由固定 px 改为比例：`部门 12% · 原等级口径 30% · 映射风险序 30% · 说明 28%`，避免宽屏下比例失衡。
- 验证：1366 / 1600 / 1920 三档均无横向溢出、无残留空白。

### B3　导入区划 → 字段表单

现状：单个 `<textarea>`，用户需自己拼「编码,名称,镇街,类型」，容易格式错。

改为结构化表单（每行一条，可「再加一条」）：

| 字段 | 控件 | 说明 |
|---|---|---|
| 上级镇街 | 下拉（20 个镇街） | 必填，决定区划归属 |
| 类型 | 下拉（社区 / 村） | 必填 |
| 区划编码 | 输入 + 自动带前缀 | 选镇街后自动补 `110228` + 镇街 3 位，如 `110228001`，只补后 3 位 |
| 社区 / 村名称 | 输入 | 必填，同镇街内不可重名 |

- 提交时逐行校验：编码前缀、编码重复、同镇街重名、必填项 → 分别计数「新增 / 跳过」并说明原因。
- 保留「批量粘贴」作为折叠的次级入口（历史习惯的用户仍可用）。

### C2　「保存草稿」的草稿在哪、怎么看

现状：

- 所有改动（权限、密级、阈值、规则、DQ、账号、字典）**逐条自动**写入草稿，无需手动保存；
- 草稿存在 `sessionStorage`，即**当前标签页会话级**：刷新不丢，关掉标签页就没了；
- 「保存草稿」按钮点开的是一个清单弹窗，能看到每条变更的模块 / 描述 / 时间——所以它实际是「查看草稿」，文案有误导；
- 发布后草稿清空，版本号 +0.1。

待确认方案（见第五节 Q2）。

### C3　提交发布后审计日志没有记录 —— 两个真 bug

**Bug 1：审计面板切页签不重新渲染**

`initTabs()` 的 `go(key)` 只做面板显示切换（page-system.js:51-58），不调用任何 render。
审计面板的 DOM 停留在页面初次加载时的快照 → 之后做的所有操作（不只是发布）都不会出现，必须手动刷新页面才能看到。

影响面：**不止发布**。在 system.html 内做任何操作再切回审计页，全部看不到。

**Bug 2：21 个动作名不在操作类型映射表里**

`OP_MAP`（page-system.js:1580）只登记了 20 个旧动作名，而实际会写入审计的动作名有 32 个。
未登记的有：发布系统配置、放弃配置草稿、修改字典项、新增字典项、调整字典排序、修改阈值参数、修改预警规则、新增预警规则、修改数据质量规则、新增数据质量规则、调整角色权限、重置角色权限、调整字段密级、调整脱敏策略、新建账号、编辑账号、维护责任人、生成权限清单、处置安全事件、导出台账、数据导入、等级变更、发起等级调整……

后果：一旦在「操作类型」下拉里选了任何类型，这些记录全部被过滤掉（落到 `other` 桶，而下拉里没有"其他"选项）。

**Bug 3（连带发现）：会话审计时间与演示日混排**

`now()` 取的是真实系统时间（2026-11-12），而演示数据日是 2026-11-10。
会话记录会以 11-12 插在 11-10 的历史记录前面，日期列看起来跳变。
`auditRows()` 也未做排序，完全依赖 `unshift` 顺序。

**修复方案**

1. `go(key)` 内按页签触发对应渲染（`audit` → 日志明细 + 完整性 + 安全事件），并统一在写操作后广播刷新；
2. 补全 `OP_MAP`，并把「操作类型」下拉从 7 项扩为分组选项（查询 / 导出 / 审批处置 / 走访 / 越权 / 登录 / 规则 / **账号 / 配置发布 / 字典** 等）；
3. `auditRows()` 按时间降序稳定排序；会话记录时间统一到演示时钟（2026-11-10），避免日期跳变。

**全站审计覆盖复查结论**

已逐个核对 `store.js` 系统管理段的全部写方法（`setRolePerm / setFieldMask / setDesens / setParam / setRule / toggleRule / addRule / setDq / addDq / setAccount / addAccount / setDictRow / addDictRow / setDictOrder / publish / discardDraft / permListAdd / setEventStatus / updateResponder` 等）——**每个都已调用 `audit()`，无遗漏**。
问题不在"没写审计"，而在"写了但看不到"（Bug 1）和"写了但筛不出来"（Bug 2）。
