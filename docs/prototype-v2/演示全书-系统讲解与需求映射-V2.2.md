### 1.2 技术形态

```
纯静态：HTML + CSS + 原生 JS，零构建、零依赖、零外链
├─ 双击 index.html 可打开（file:// 亦可，但导入 xlsx 建议 http）
├─ 状态存 sessionStorage（关标签页即清），配置草稿存 localStorage（关标签不丢）
└─ 数据全部虚拟生成（mulberry32 固定种子，每次刷新同一份数据）
```

一句话讲法：**"刻意做成零依赖，是为了让领导在任何一台内网机器上双击就能看，不装环境、不连数据库。"**

R1 区委书记/区长（2 人，全区只读、姓名掩码）· R2 政法委主管（6）· R3 部门科长/主任（9，本部门可写+本类别全区统计）· R4 部门经办（12，仅本部门来源）· R5 属地经办（10，本辖区可写走访）· R6 属地负责人（5，本辖区审核+零报告）· R7 系统管理员 / R8 安全管理员 / R9 安全审计员（三员分立，各 1 人，**不触业务数据**）
合计 **47 个账号**，**48 项权限码（5 组）**，**9 个字段密级**。

> 讲法：**"权限分三级——区领导看全局概要、科长和主管部门审核管理、经办部门只维护本部门数据，会上说的三级，在系统里对应 R1–R6 六个业务角色加三员分立。三员分立是为了等保三级：管系统的、管权限的、管审计的不能是同一个人。"**

**字段级掩码的实现**：`DATA.field(roleKey, fieldName, person)` 返回 `{text, masked}`，页面渲染时带"掩码"小锁标；同一个页面，换个角色刷新，同一行数据就换一种展示。

### 1.8 全站贯通的 6 条逻辑主线（讲故事的骨架）

```
主线① 数据进来：导入(真解析) → 查重 → 落库 → 台账/驾驶舱指标同步
主线② 一人一档：台账 → 点人 → 档案(22 字段+3 标签上限+依据) → 走访登记 → 回写台账
主线③ 风险动起来：档案/批量 → 发起等级调整 → 审批(回避+多级) → 通过后全站等级同步
主线④ 该管未管：规则(RG-01~13) → 预警待办 → 处置 → 转派 → 闭环 + 同步写走访
主线⑤ 盲区化解：双在册/多标/未定级 → 并档 or 补评 → 生成审批单 → 盲区化解数变化
主线⑥ 留痕收尾：以上每一步 → 审计日志(哈希链) → 明文访问专项 → 安全事件
```

**这 6 条主线就是 §2 演示动线的编排依据。**

### 6.3 可能被追问的 12 个问题与标准答法

| 问题 | 标准答法 |
|---|---|
| 这套东西和公安现有系统什么关系？ | 数据边界分开，靠身份证做去重与比对；一期不碰公安专业模型 |
| 6,028 和 7,112 差在哪？ | 7,112 是各部门台账人次（一人多档），6,028 是按身份证去重后的人数，差额就是重复建档 |
| 为什么 486 人而不是 6,028 人都管？ | 486 是风险等级较高的（高风险及以上），6,028 是全量在册；管控资源按风险序分配 |
| 待核实 612 人为什么不并进 486？ | 未定级/风险不详，缺依据不能算进高风险统计；它们进"盲区"单独盯，补评后再定级 |
| 等级下调会不会被滥用？ | 下调必须给依据（≥15 字）、走多级审批、发起人回避、下调后 7 日无随访自动预警（RG-05） |
| 明文导出会不会泄露？ | 默认脱敏；明文要申请+用途+有效期；≥50 条双人复核；文件首行水印；全程审计 |
| 数据不准怎么办？ | 6 条数据质量规则（校验位/必填/枚举/属地/日期/重复）+ 报送进度与催办 + 完整性率考核 |
| 各部门凭什么配合？ | 报送进度表按月推政法委，迟报自动标注（如司法局迟报 3 天），纳入考核 |
| 重点时期结束后怎么办？ | 响应等级切回三级（每月见面/月报），时期参数可配，历史回填记录留档 |
| 能不能接 Pad？ | 是响应式布局，1440 以上自适应一屏；大屏另有 1920×1080 专版 |
| 什么时候能真用？ | 脱敏表头与字段标准一到位，导入模块即可接真实数据；其余模块逻辑已通 |
| 这套花了多少工作量？ | 14 个页面、9 个公共资产、约 1.4 万行前端代码，零依赖 |
